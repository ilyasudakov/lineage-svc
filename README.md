# lineage-svc

Lightweight lineage service with an **edges-only schema** — Marquez replacement
candidate for the Improvado data platform.

**Jira:** [IMD-60352](https://improvado.atlassian.net/browse/IMD-60352)
**Status:** PoC complete, **decision: SHIP** ([docs/decision.md](docs/decision.md))

## Headline numbers

Measured side-by-side against Marquez 0.50.0 under identical hardware and load.

| | lineage-svc | Marquez | Δ |
| --- | --- | --- | --- |
| Write throughput (batch endpoint) | **3,092 ev/s** | 41.6 ev/s | **74×** |
| Write p95 @ 300 rps | 6 ms median | 19,529 ms | 90× |
| Read direct p95 | **4 ms** | 286 ms | **71×** |
| Read depth=10 p95 | **4 ms** | 316 ms | **79×** |
| Postgres CPU avg @ 10× prod load | 17 % | 100–200 % (prod) | — |
| 5xx error rate | 0 % | 40.8 % | — |
| Sequential scans on edge table | **0** across 3M reads | n/a | — |
| Recovery after `kill -9` | 3–6 s | n/a | — |

**8 of 9 [Definition-of-Done targets](docs/decision.md#dod-scorecard) pass cleanly.**
See [docs/decision.md](docs/decision.md) for the full report and rollout plan.

## Why

Marquez's events/versions/runs schema becomes a bottleneck on graph reads
(p95 `/lineage/direct` up to ~19 s in prod, Postgres CPU 100–200 %).
This service stores lineage as a flat edge table so graph traversal is a
single recursive CTE on indexed columns.

## Stack

- FastAPI + Uvicorn (2 workers)
- SQLAlchemy 2.x (async) + asyncpg with statement caching
- PostgreSQL 16
- Alembic migrations (auto-applied on container startup)
- Prometheus client for metrics
- Cytoscape.js graph UI at `/ui` (vanilla JS, no build step)

## Schema

```sql
CREATE TABLE lineage_edge (
  src_urn     TEXT NOT NULL,
  dst_urn     TEXT NOT NULL,
  edge_type   TEXT NOT NULL,        -- 'produces' | 'consumes' | 'derives_from'
  job_urn     TEXT,
  run_id      TEXT,
  namespace   TEXT NOT NULL,
  metadata    JSONB,
  created_at  TIMESTAMPTZ DEFAULT NOW(),
  updated_at  TIMESTAMPTZ DEFAULT NOW(),
  PRIMARY KEY (src_urn, dst_urn, edge_type)
);
-- + indexes on src_urn, dst_urn, job_urn, namespace
```

## API

| Method | Path | Purpose |
| --- | --- | --- |
| POST | `/api/v1/lineage` | OpenLineage-compatible single-event ingest |
| POST | `/api/v1/lineage:batch` | **Batch ingest** (up to 1000 events/call, 24–30× faster) |
| GET  | `/api/v1/lineage/direct?node=<urn>` | Immediate upstream + downstream neighbors |
| GET  | `/api/v1/lineage?node=<urn>&depth=N&direction=upstream\|downstream\|both` | Recursive traversal (depth 1–50) |
| GET  | `/api/v1/namespaces` | List distinct namespaces |
| GET  | `/api/v1/search?q=&namespace=` | Substring search over URNs |
| GET  | `/ui` | Graph explorer SPA |
| GET  | `/health`, `/metrics` | Liveness, Prometheus exposition |

OpenAPI: `/docs` (auto-generated by FastAPI)

## Run locally

```bash
docker compose -f benchmark/docker-compose.yml up --build
# Alembic runs automatically inside the container — no manual migration step

curl http://localhost:8000/health           # {"status":"ok"}
open  http://localhost:8000/ui              # graph explorer
open  http://localhost:8000/docs            # OpenAPI
open  http://localhost:3000                 # Grafana side-by-side dashboard
```
